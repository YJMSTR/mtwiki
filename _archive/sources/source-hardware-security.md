## 摘要

硬件木马（Hardware Trojan）是集成电路设计中极其隐蔽的安全威胁，攻击者可在 RTL 设计阶段植入恶意逻辑，在特定触发条件下泄露密钥、篡改功能或导致拒绝服务。本文综述了 RTL 级硬件木马检测的最新技术路线，包括：基于仿真的逻辑测试与统计方法、AI 驱动的图神经网络/大语言模型检测、形式化验证（Formal-PCH / QIF-RTL）、以及 Trust-Hub 基准测试集在开源仿真工具链（Verilator / OpenROAD / Yosys）中的应用。预硅（pre-silicon）检测是降低流片后修复成本的关键环节，而 RTL 级多线程仿真器可大幅加速检测所需的数百万次仿真迭代。

## 关键要点

- **Trust-Hub 基准集**：业界公认的硬件木马检测基准数据集，包含 AES、RS232、PIC、VGA 等经典设计的带木马版本，广泛用于验证检测算法。
- **UCI（Unused Circuit Identification）**：通过代码覆盖率分析识别 RTL 中从未被触发的逻辑，这些"死逻辑"可能是木马触发电路。但先进木马可利用低概率事件规避检测。
- **AI 辅助检测**：GNN（图神经网络）自动提取 RTL 结构特征；LLM（如 Llama 3.3）在角色扮演提示优化下对 Trust-Hub 数据集的检测准确率达 91%，但 70B 参数规模以下模型泛化能力有限。
- **开源工具链**：Yosys（开源综合）+ ModelSim（仿真）+ Verilator（快速仿真）+ OpenROAD（布局布线）构成了可复现的 RTL 安全验证流水线。
- **形式化验证工具**：Formal-PCH（Proof-Carrying Hardware）和 QIF-RTL 可在 RTL 级证明安全属性，如信息不泄露、功能未被篡改等。
- **Design for Trust**：在设计阶段增加可测性（testability）和断言（assertion），使安全验证更紧密地融入标准功能验证流程。

## 对 RTL 仿真器多线程化的启示

1. **大规模仿真需求**：Trust-Hub 基准测试和 UCI 方法都需要对 RTL 设计进行海量随机测试向量仿真，单次检测 campaign 可能涉及数百万次仿真运行。多线程仿真器可将这些独立的仿真批次并行执行，线性缩短检测时间。

2. **AI 检测的推理加速**：GNN 和 LLM 检测方法需要在 RTL 设计上反复执行前向推理，若仿真器支持多线程，可在多个线程上同时处理不同设计模块或不同测试向量，显著提升 throughput。

3. **覆盖率导向的并行仿真**：安全验证中的断言覆盖率和代码覆盖率收集天然适合并行化——每个线程独立运行不同测试子集，最后合并覆盖率数据。这要求多线程仿真器在共享内存模型下支持高效的覆盖率合并。

4. **功耗侧信道联合分析**：木马检测中的侧信道分析（如动态电流监测）需要在仿真中同步采集功耗轨迹。多线程仿真可以分片采集不同时间窗口的功耗数据，再通过离线分析关联。

## 原文摘录

> "We simulate hardware Trojans and architectural vulnerabilities in RTL designs using open-source toolchains like Verilator and OpenROAD. Trust-Hub benchmarks will serve as the primary dataset, providing ground-truth examples of Trojan-inserted netlists. AI-based FSM anomaly detectors and graph-based classifiers will be compared against rule-based verification approaches and SAT-based deobfuscation attacks."
> —— ICAir 2025 论文

> "Hardware Trojan attacks are a major security concern for integrated circuits (ICs) vendors. It entails the malicious modification of an IC during the design stage or the manufacturing stage. The attacker with access to the RTL code of the IC at the design house can insert a stealthy Trojan in the design code to evade detection during post-manufacturing testing."
> —— CAD for Assurance

> "In the Post-Quantum Cryptography study case with 196 complex designs from 4 different algorithms, the proprietary models could detect trojans generated by open-source model with an accuracy up to 91%, with smaller influence of the prompt when compared to the detection accuracy of open-source LLMs to detect trojans generated with a proprietary model."
> —— Hayashi 博士论文 (USP, 2025)

> "We employ standard HDL, assertion language and functional verification tools that are familiar to hardware designers as much as possible, especially open source synthesis and verification tools when available. This eliminates the requirement for dedicated automatic test pattern generation or security verification tools and allows security verification to be more closely integrated into functional EDA flow."
> —— Design for Assurance: Employing Functional Verification Tools for Thwarting Hardware Trojan Threat
