# 生成代码仿真器的 A/B 隔离纪律

## 概述

生成代码仿真器上做一次性能假设检验的成本结构很特殊：每个实验侧是一次**完整的生成 + 编译**（分钟到小时级），两份二进制之间可能隔着数千个生成源文件的任意差异。归因因此极其脆弱——任何顺着补丁混进二进制的额外机件（哪怕运行时根本不执行）都会污染测量。案例库中记录过一次完整事故链：一个"5/5 对全负、-2.54%"的头条数字，事后发现二进制里混入了未门控的机件，撤回重测后方向**翻转**为 +3.46%（噪声内），真效应 ≈ 0。

本文把这条事故链反推成纪律：三条隔离铁律（§1）、事故链全程复盘（§2）、匹配对照构建方法（§3）、噪声与符号一致性判定（§4）、不可判定结果的处置（§5）、发射前可捕获的生成器陷阱（§6），最后是检查清单（§7）。普查类工具的配套纪律见 [[wiki-value-change-census]]，具体 A/B 实验（条件存储）的形态见 [[wiki-conditional-store-elision]] §5。

## 1. 三条铁律

### 1.1 flag-off 字节恒等

**每个新代码生成 knob 从诞生起必须默认关闭，且关闭时生成器输出与打补丁前逐字节恒等。**

- 验证范围不能只有小设计：案例在 6 个小 FIR 设计 + 完整稠密配方 + 21 分片并行构建上逐文件 diff；另一次在 1221/1221 个生成源文件上证明恒等，并核对关闭态 emu 二进制体积与补丁前相等。
- 为什么逐字节而不是"功能等价"：生成文本是 schedule 结构的载体，一处看似无害的文本漂移（多一个声明、换一处顺序）可能改变内联/布局/对齐，进而改变性能基线。字节恒等让"控制侧 == 历史基线"成为**定理**而不是假设。
- 与 [[wiki-pointer-order-nondeterminism]] 互补：那边保证同一生成器自身的确定性（指纹可复现），这边保证 knob 关闭时新生成器 ≡ 旧生成器。两者合起来，A/B 的控制侧才有资格代表"未改动世界"。

### 1.2 单变量规则：diff 必须被被测特征完全解释

治疗侧与控制侧的**全部**差异（文件数、hunk 内容）必须能归到被测特征名下。理想形态：两份产物只差**一个**文件、其中每个 hunk 都位于被测 knob 门控的代码块内。案例的合格样本：c2 vs w2 恰差一个 `SimTop803.cpp`，两个 hunk 全部是 TRIM 门控特征（发布循环 @154220、启动容量断言 @154334）——"一个变量（TRIM 特征集）仍然完全解释 diff"。

反例即 §2 的事故：diff 里混入了第二个特征（owner-map 机件 + 变更的 spawn guard），单变量规则被破坏，-2.54% 无法归因给 TRIM。

### 1.3 runtime-inert ≠ 文本恒等

**运行时不执行的代码仍然是混杂变量。**补丁里"顺手"带上但当前配置不激活的机件（默认关闭的 map 表、多一条分支的 guard）违反字节恒等：它改变二进制布局、icache 对齐、编译器决策——这些都是真实的性能通道。"这段代码现在不会跑，所以无害"是生成代码仿真器上最危险的一句安慰剂。

规则化表述：**每个新发射必须从出生起就在默认关闭的 codegen knob 之后**；不存在"先无条件发射、之后再补门控"的过渡态。凡是在无门控状态下混入过二进制的测量，一律不得作为证据。

## 2. 事故链复盘：一个头条数字的撤回

案例完整链条（每一步都是可迁移的判定点）：

| 步骤 | 内容 | 教训 |
|---|---|---|
| 1. 构建对照 | 控制侧用**旧生成器**（C），治疗侧用补丁生成器（W） | 对照不匹配：C 与 W 隔着整个补丁，不是单变量 |
| 2. 混杂入体 | W 的模型里除被测特征外还**无条件**含 owner-map 机件 + 变更的 spawn guard | 违反 §1.1/§1.3：runtime-inert 机件照常进文本 |
| 3. 测量 | C vs W = **-2.54%，5/5 对全负** | 统计上无懈可击，归因上完全错误——好看的一致性掩盖不了混杂 |
| 4. 撤回 | 评审指出混杂 → 该轮**整轮撤回为证据** | 撤回要撤数字本身，不是加脚注 |
| 5. 补门控 | 两个特征各自获得默认关 knob（TRIM 门控发布循环+启动断言；MAP 门控机件+guard，关闭态逐字复现上游块） | 补救 = 让铁律从此成立，commit 记录 knob 语义 |
| 6. 恒等证明 | 关闭态 1221/1221 文件字节恒等；emu 体积相等 | §1.1 的验证形态 |
| 7. 匹配对照 | 同一补丁生成器构建 c2（knob 全关）与 w2（仅 TRIM 开） | 控制与治疗同源，diff 收缩到一个文件两个 hunk |
| 8. 重测 | c2 vs w2 = **+3.46%，对值混合** | 方向翻转 + 幅度在会话噪声内 |
| 9. 判定 | 真效应 ≈ 0，route 关闭，默认不变，knob 留存 | 零结果也是结果；headline 的反转**全程记录在案** |

第 3→8 步的方向翻转是整个链条最有教育意义的事实：**混杂的效应量（-2.54%）可以和真效应、噪声同一量级**，只有消除混杂后才看得清真效应是零。

## 3. 匹配对照构建方法

事故后的标准操作：

1. **同一生成器、同一配方、同一种子回放**构建控制侧（knob 全关）与治疗侧（仅被测 knob 开）。两边 schedule 结构逐文件恒等（种子回放门禁 + 结构数校验：任务数、token 数、规范点 9/9）。
2. **构建标志成对**：codegen knob（生成期）与 compile knob（`-D..._COMPILE=1`，编译期）必须同步开/关——只开一头会得到"生成了机件但没编译进支持代码"或反之的半开状态。
3. **diff 审计作为门禁**：列出全部差异文件与 hunk，逐个归因到被测特征；出现任何归因不上的 hunk → 回到 §1.3，测量作废。
4. **同型运行环境**：两侧同 `taskset`、同线程数、同执行器模式；被测特征需要的环境变量只出现在治疗侧命令行（案例 map 实验中"env 是唯一差异"的 w3 形态）。

## 4. 噪声纪律：配对、符号一致与方向翻转

### 4.1 外部负载机器上的决策量

共享机器上（案例：机器携带 omp/kimi 外部负载、亲和性 0-383）绝对墙时间不可比，会话噪声实测 ±3–4%。决策量因此是**配对同会话差值**：

- **交错配对**：a/b 交替运行（A1 B1 A2 B2 …），每对计算 B−A；
- **符号一致性门槛**：只有全部（案例 5/5）对同号才可晋级为方向性结论；
- **幅度 vs 噪声**：|均值| 在会话噪声内 + 对值混合 → 判零（true effect ≈ 0），无论方向。

### 4.2 方向翻转即判零

同一对照在两轮中给出 -2.54% 与 +3.46%（两轮都"5/5"或接近全负/全正的表象之下对值实际混合）——**方向都不稳定的效果不存在可估计的符号**。判零、关闭 route、不动默认值。比"再多跑几轮取平均"诚实：取平均只会给零效应戴上虚假的置信区间。

### 4.3 不可判定但方向性可疑的结果

案例 owner→CPU 显式映射：两轮均值都为负（-1.00%、-4.20%），但符号不一致（2 强负对 + 3 平）。处置：

- **不得晋级**（不满足符号一致性）；
- 但也不得判零丢弃——两轮同向均值提示外部负载下可能存在小的真效应（显式绑定或可抗迁移扰动）；
- 正确出口：**"仅空闲机器确认可作出默认决策"**，knob 保持默认关。把"证据不足"与"效应为零"区分开，前者保留复测路径。

### 4.4 正确性门禁贯穿每一侧

每次测量运行（含每个配对分支）过体系结构精确参考门禁（NEMU instrCnt 精确匹配）。性能归因再干净，正确性不过关的运行全部作废——门禁在 A/B 脚本里以断言形式存在，失败即中止汇总。

## 5. 零结果与 knob 的遗产

一个被判定为零/负的实验留下的永久资产：

1. **默认关 knob + 已证明的 flag-off 恒等**：未来任何一次空闲机器复测只差一个环境变量；
2. **测量纪律链本身**（混杂被捕获 → 匹配对照修正 → headline 反转 → 全程记录）：比"实验成功"更有训练价值的证据；
3. **route 关闭记录**：防止同一假设在无新证据时被重复开仓。

这与"rejected probe 之后必须继续下一个候选而非提前收工"的迭代纪律衔接：关闭一条 route 的同时，下一个候选（及其**自己的**普查/门控前置）已在队列里。

## 6. 发射前评审：测量之前的陷阱

案例中两类生成器缺陷由评审在**测量之前**捕获（每类一旦漏网都是一轮作废的测量）：

- **printf 风格发射器的 `%%` 转义**：`emitBodyLock(fmt, ...)` 这类按 printf 语义消费格式串的发射函数里，生成代码中的字面 `%` 必须写成 `%%`（详见 [[wiki-value-change-census]] §3.2）；
- **spawn-guard 完整性**：新机件改变 worker 启动路径时，guard 覆盖所有启动分支（案例：worker 0 也必须被 map 模式绑定；`pthread_setaffinity_np` 返回值不得忽略，失败必须 abort）。

方法论要点：**在构建二进制之前对生成的源码文本做一轮"恒等性 + 完整性"评审**，比在测量之后用撤回链兜底便宜两个数量级。评审清单就是 §1 三铁律 + §3.3 的 diff 审计。

另一个跨任务教训：**已验证 knob 的有效性不免费跨执行器存活**——配方/执行器改动后，曾经的默认关 knob 需要重新过恒等与正确性门禁（案例：seed2 复用在 champion 配方上先后暴露两个潜伏 bug，其中一个仅在长跑长度才现形的非原子激活写）。复用 knob = 复用其验证义务。

## 7. 检查清单

1. 新发射从出生起在默认关 knob 后；无门控过渡态。
2. flag-off 逐字节恒等：小设计集 + 完整配方 + 分片构建；emu 体积相等。
3. 控制与治疗**同生成器**构建；codegen 与 compile 标志成对。
4. diff 审计：全部 hunk 归因到被测特征，归因不上即作废。
5. runtime-inert 机件按混杂处理；"不会跑"不等于"不进来"。
6. 交错配对、同会话；符号一致才晋级；方向翻转判零。
7. 每侧每次运行过正确性门禁（断言式，失败即中止）。
8. 不可判定但同向的结果 → 留默认关 knob + 空闲机复测路径，不晋级不丢弃。
9. 测量前对生成文本做恒等性/完整性评审（`%%` 转义、guard 全覆盖）。
10. 配方/执行器变更后重新验证所有在用 knob。
