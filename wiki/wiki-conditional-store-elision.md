# 条件存储与写省略：周期仿真器中跳过幂等写为何失败

## 概述

变值普查（见 [[wiki-value-change-census]]）在周期精确仿真器上几乎总会给出一个诱人的数字：**96–97% 的寄存器状态写写入的是旧值**（案例：25.7 万站点、86 亿次存储事件中 96.3% 不变）。直觉方案是把每个状态存储改成条件存储——`tmp = rhs; if (cur != tmp) cur = tmp;`——"省掉"96% 的写流量。

案例的判定实验给出相反结论：**同一 schedule 结构、5 对交错 A/B、全部通过体系结构精确门禁（NEMU）的测量中，条件存储比无条件存储慢 17.94%，5/5 对全负**；同时生成文本膨胀 12.7%。这不是测量噪声，是机制性失败。

本文拆解为什么高不变写比例是**必要而不充分**条件：被省的流量本来就不贵（§3），而省略机制本身有恒定成本（§2）与结构性副作用（§4）；给出判定实验的正确形态（§5）；最后列出条件存储**可能**获胜的条件与更合理的替代杠杆（§6）。

---

## 1. 幂等写库存：它从哪来，规模多大

### 1.1 来源

周期精确执行器每个周期对全部状态重算 next-state 并写回。采样式电路（处理器核、总线桥）在稳态下大部分状态寄存器保持不变：控制寄存器位段、队列条目的编码位、握手信号的粘滞值——next-state 函数重算出的值与已存值相同。于是"写"退化为幂等写：写前写后内存状态不变。

关键点：这个库存**只能普查得到**（[[wiki-value-change-census]] §1——指令数比值等活动性间接证据对写值分布不构成界）。案例双长度验证（97.25% @ 1x / 96.30% @ 10x）确认其为稳态现象。

### 1.2 库存结构决定可利用性

单看总量会误判。库存按站点类别分布不均：

- 位宽：w1/w8/w32/w64 各类占比不同；比较窄值便宜、比较宽值贵；
- 站点热度：不变写集中在**冷站点**（每周期都执行但值很少变的控制状态）还是**热站点**（高频翻转）决定省略的命中率分布——案例逐宽度分类普查正是为此；
- 排除类：数组拷贝、多字宽目标、内存写端口根本不在可条件化种群内（案例约 2.5 万站点被结构性排除）。

省略机制是**按站点发射、按事件付费**的：它对每个站点无差别地加成本，只对"不变事件"省钱。库存的**分布**比总量重要。

## 2. 成本模型：恒定成本 vs 按事件节省

### 2.1 不对称的付费结构

| 项 | 付费时机 | 规模 |
|---|---|---|
| compare+branch | **每个事件**（含 4% 变化的那部分） | 案例全部站点每秒数亿次执行 |
| 跳过的 store | 仅不变事件（96%） | 与总存储事件同量级 |
| 文本膨胀 | 每次 icache miss、每次取指 | +12.7% 文本（无条件 → 条件形态） |

省略方案的净收益 ≈ (跳过的 store 单价 × 96%) − (compare+branch 单价 × 100%) − 文本税。**store 与 compare 的单价差远小于直觉**：单字 store 命中 L1/存储缓冲时约 1 个周期量级，compare+branch 即便完美预测也占前端发射槽。单价差 × 命中率不足以翻正，是 17.94% 净损失的第一来源。

### 2.2 分支的隐藏成本

在**直线化/深内联**的生成代码体（案例热函数是巨型直线块，占执行时间 ~60%）里插入条件分支有两重代价：

1. 打断前端取指流：直线代码的低分支误预测率（对照 ESSENT 的 0.1% vs 22%，见 [[wiki-chisel-and-essent]]）正是这类执行器快的原因之一；每站点一个分支把这项优势按站点数稀释；
2. 阻断编译器整合：无条件存储序列可被合并/重排（store 对 store 无数据依赖时），条件化后每个存储携带控制依赖，优化空间收缩。

## 3. 被省的流量本来就不贵：吸收效应

跳过写流量能省钱的前提是**那些写在关键路径上**。实测机制拆解表明它们不在：

1. **存储缓冲 + 写合并**：同值/同行的重复写进入存储缓冲后被合并，到不了 LLC；"写流量"在计数器上巨大，在内存系统里被前端结构吸收。
2. **缺失压力在读侧**：案例 perf 剖析中 L2 请求缺失占 74%，但进一步归因显示缺失由**读侧**（取指 + 数据读）主导——省掉写流量不削减主要缺失来源。（注意计数器语义：硬件计数的是**请求数**而非传输字节，由 IPC<1 直接推断"带宽受限"需要循环归因证据，案例仅记录为观察。）
3. **写不是复发回路的一部分**：静态调度执行器的墙时间下界由调度关键回路（initiation interval，II）决定——案例中是问题队列唤醒回路；被省的写全部落在回路内部的直线段上，减掉它们不移动 II 下界（墙 = max(II, T/N) 体制下尤甚）。

> 通用教训：**"省掉 X% 的事件"与"省掉 X% 的时间"之间隔着"被省事件的单价 × 它是否在关键路径上"两个因子**。普查只给了第一个因子的分子；第二、三因子要靠剖析与 A/B。

## 4. 文本膨胀的 icache 税

条件形态比无条件形态多出临时变量物化、比较、分支与作用域括号——逐站点累加后案例文本 +12.7%（215MB → 242MB）。这份税在生成代码仿真器上是**硬成本**：

- 热循环的取指足迹按比例扩大，icache miss 与前端压力上升（[[wiki-simd-and-icache]]）；
- 与 §2.2 叠加：更多分支 + 更大足迹 = 直线化执行器的两项核心优势同时受损；
- 带计数器的中间形态更糟（+35.7% 文本 + 每事件原子 RMW，见 [[wiki-value-change-census]] §4.1）——测量装置与被测形态必须分离。

---

## 5. 判定实验的正确形态

案例 A/B 的设计要点（全部必要，缺一则结论可争议）：

1. **最简发射**：`tmp = rhs; if (cur != tmp) cur = tmp;`——零计数器、零附加护栏。被测的就是机制本身，不是某个笨重实现。（先行形态带着计数器测过，直接不可测地慢，教训是执行形态必须剥离一切测量装置。）
2. **同一 schedule 结构**：控制与治疗侧用同一 schedule 种子回放生成，任务图、归属、生成结构逐文件恒等——唯一差异是存储站点形态（隔离纪律见 [[wiki-ab-isolation-discipline]]）。
3. **5 对交错运行**：a/b 交替执行，配对差值为决策量；案例 5/5 对全负（+17.94% 均值），符号一致才可判负。
4. **每侧正确性门禁**：全部 10 次运行过体系结构精确参考（NEMU）——条件存储是语义改动，正确性证据与性能证据同权重。
5. **产物侧记录文本体积**：文本膨胀是机制的一部分，必须与性能同时入账。
6. **结论的边界声明**：A/B 否决的是"在**全部**合格站点发射**动态** compare+branch"这一实现族；它不同时否决抽样条件化、宽目标专化、静态省略等变体（§6）。

## 6. 条件存储何时可能赢：条件清单与替代杠杆

### 6.1 可能获胜的条件

条件存储不是永远错误，它在以下条件**逐项成立**时才值得再试：

| 条件 | 原因 |
|---|---|
| 单次写远贵于一次比较 | 未缓存/设备内存写、跨 NUMA 远端写、非临时存储 |
| 比较显著窄于写 | 宽向量/多字目标：一次窄比较挡住多字存储（案例把宽目标排除在种群外，正是失去这一获利面） |
| 不变写集中在**热**站点且真值瓶颈在写端口/存储缓冲饱和 | 省略命中的是关键路径事件 |
| 站点数少而单站点事件量巨大 | 文本税与分支税按站点数计，收益按事件量计 |
| 可抽样（1-in-N 条件化）或由 PGO 挑出高命中站点 | 把恒定成本从"全部站点"收缩到"获利站点" |

### 6.2 替代杠杆（同一库存的不同变现方式）

- **静态无消费者省略**：分析写后是否有任何读者（案例：8.35% 状态写无消费者），无消费者则**编译期**删除——零运行时成本、零分支、文本反而缩小。同一份普查基础设施即可支撑。
- **读侧普查先行**：写侧省略失败后，下一个假设（无效读负载）必须先做自己的读侧普查——同样的 census-before-emit 纪律（[[wiki-value-change-census]]）。
- **值不变传播到上游**：若 next-state 函数对输入子集恒等，跳过**计算**而非存储（不动存储形态，无文本税）。
- **分组脏标记**：一个位图/epoch 位保护一组状态，组级比较代替逐站点比较——把 compare 次数从站点数降到组数。

## 7. 一页总结

- 96–97% 不变写是真实库存，但只是**必要条件**；条件存储按站点付恒定成本、按事件收窄价节省，两端单价差撑不起净收益（+17.94%，5/5 全负）。
- 被省的写流量被存储缓冲/写合并吸收，缺失压力在读侧；不在关键回路上的事件省了也不省时间。
- 文本膨胀（+12.7%）是直线化执行器的硬税：更大取指足迹 + 更多分支。
- 判定实验必须最简发射、同结构、配对交错、双侧正确性门禁、文本入账、结论限定到被测实现族。
- 下一步永远是**静态**杠杆（无消费者省略）或**先普查**的新方向（读侧），而不是换一种动态包裹。
